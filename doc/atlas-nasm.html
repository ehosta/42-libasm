Atlas NASM x86-64

Tout ce qu'il faut pour lire, écrire et déboguer de l'assembleur 64 bits sous Linux, jusqu'à réécrire des fonctions de la libc. Chaque exemple complet de cette page a été assemblé avec NASM 2.16 et testé.

.loop:label
movmnémonique
rax,destination
[rdi + rcx*8]source
; tab[i]commentaire

Une ligne d'assembleur, c'est une instruction du processeur, écrite presque telle qu'il l'exécute. Il n'y a ni variables, ni types, ni boucles : seulement 16 cases de 64 bits (les registres), de la mémoire vue comme un grand tableau d'octets, et des sauts. Tout le reste est une convention, et cette page les passe en revue une par une.

01

Point de départ

Du fichier .asm au binaire, et la forme minimale d'un programme.

NASM traduit ton fichier en fichier objet ELF64 (.o) : du code machine, plus une table de symboles. L'éditeur de liens (ld, ou gcc qui l'appelle) colle les objets ensemble et produit l'exécutable.

# programme autonome, sans libc : le point d'entrée est _start
nasm -f elf64 hello.asm -o hello.o
ld hello.o -o hello

# fonctions appelées depuis du C, ou qui utilisent la libc : gcc fait le lien
nasm -f elf64 ft_strlen.asm -o ft_strlen.o
gcc main.c ft_strlen.o -o test

# une bibliothèque statique façon libasm
ar rcs libasm.a ft_strlen.o ft_strcpy.o

# symboles de debug pour gdb
nasm -f elf64 -g -F dwarf ft_strlen.asm

Le plus petit programme utile : il demande au kernel d'écrire un message, puis de terminer le processus.

; hello.asm : affiche un message puis quitte, sans libc
global _start

section .rodata
msg:    db "Hello, world!", 10      ; 10 = '\n'
len:    equ $ - msg                 ; taille calculee a l'assemblage

section .text
_start:
    mov eax, 1          ; numero du syscall : write
    mov edi, 1          ; arg 1 : fd = stdout
    lea rsi, [rel msg]  ; arg 2 : adresse du buffer
    mov edx, len        ; arg 3 : nombre d'octets
    syscall

    mov eax, 60         ; numero du syscall : exit
    xor edi, edi        ; arg 1 : code de retour 0
    syscall
  • global _start rend le symbole visible du linker. Sans ça, ld ne trouve pas le point d'entrée.
  • section .rodata contient les données constantes, section .text le code.
  • Il n'y a pas de ret à la fin de _start : personne ne l'a appelé, il n'y a nulle part où revenir. On termine avec le syscall exit.
  • Avec gcc, c'est la libc qui fournit _start et appelle ton main, qui lui se termine par un ret normal.

Registres

Seize registres généraux de 64 bits. Ils sont tous interchangeables pour le calcul ; ce qui les distingue, c'est le rôle que la convention d'appel leur donne.

Explorateur · clique un registre

Les sous-registres et le piège des 32 bits

Chaque registre se lit par morceaux : rax (64 bits), eax (32 bits bas), ax (16), al (8). Ce sont des vues sur la même case, pas des registres séparés. La règle à retenir par coeur :

  • écrire dans la vue 32 bits met les 32 bits hauts à zéro ;
  • écrire dans une vue 8 ou 16 bits laisse le reste intact.
Démonstration · rax, octet par octet
Octet de poids fort à gauche. Clique une écriture pour voir ce qui change.
Conséquence pratique

mov eax, 1 et mov rax, 1 donnent le même résultat, mais la version 32 bits est plus courte en code machine. À l'inverse, mov al, [rdi] laisse 56 bits de vieilles données dans rax : pour charger un octet proprement, c'est movzx eax, byte [rdi].

Les registres qui ne sont pas généraux

RegistreRôle
ripAdresse de la prochaine instruction. On ne l'écrit jamais directement : ce sont jmp, call et ret qui le modifient. On peut s'en servir pour adresser des données : [rel msg].
rflagsLes drapeaux (ZF, SF, CF, OF...) mis à jour par les instructions de calcul et lus par les sauts conditionnels. Détail au chapitre 07.
xmm0 à xmm15128 bits, pour les flottants et le SIMD. Les double passent dans xmm0-xmm7 et reviennent dans xmm0. Tous caller-saved.

03

Syntaxe

NASM utilise la syntaxe Intel : la destination d'abord, la source ensuite. mov rax, rbx se lit comme rax = rbx.

label:    mnemonique  destination, source    ; commentaire

.loop:    add  rax, [rdi + rcx*8]     ; rax += tab[rcx]
          inc  rcx                    ; un seul operande
          ret                         ; aucun operande

Tout est insensible à la casse sauf les noms de labels. L'indentation est libre. Une instruction par ligne.

Les nombres et les chaînes

mov eax, 42             ; decimal
mov eax, 0x2A           ; hexadecimal (ou 2Ah)
mov eax, 0b101010       ; binaire
mov eax, 'A'            ; code du caractere : 65
mov eax, -1             ; complement a deux : 0xFFFFFFFF

Labels locaux

Un label qui commence par un point appartient au dernier label normal déclaré au-dessus. Tu peux donc avoir un .loop dans chaque fonction sans conflit : le vrai nom est ft_strlen.loop.

ft_strlen:
.loop:              ; en realite ft_strlen.loop
    jmp .loop

ft_strcpy:
.loop:              ; en realite ft_strcpy.loop, aucun conflit
    jmp .loop

Opérandes

Une instruction travaille sur trois sortes de choses : un registre, une valeur immédiate, ou une case mémoire.

SorteExempleCe que c'est
Registrerax, edi, clLe contenu du registre.
Immédiat42, 'a', msglenUne constante écrite directement dans l'instruction.
Mémoire[rdi], [rbp - 8]Les crochets signifient « ce qu'il y a à cette adresse ». C'est l'opérateur * du C.
La distinction centrale

mov rax, rdi copie la valeur de rdi. mov rax, [rdi] lit 8 octets en mémoire à l'adresse contenue dans rdi. Sans crochets, on ne touche jamais la mémoire.

Le calcul d'adresse

Entre les crochets, le processeur sait calculer une seule forme : base + index × échelle + déplacement. L'échelle vaut 1, 2, 4 ou 8, c'est-à-dire la taille d'un élément de tableau.

La taille de l'opération

  
Quand un registre apparaît, sa taille fixe celle de l'opération. Quand il n'y a que de la mémoire et un immédiat, NASM ne peut pas deviner et refuse d'assembler : il faut le dire.

  
mov [rdi], al           ; ok : al fait 1 octet
mov [rdi], 0            ; erreur : operation size not specified
mov byte [rdi], 0       ; ok : ecrit 1 octet   (*p = '\0')
mov qword [rdi], 0      ; ok : ecrit 8 octets  (*pp = NULL)

mov rax, [rdi]Lit la mémoire. Les deux opérandes ont la même taille.

    
movzx eax, byte [rdi]Lit un octet et complète avec des zéros : pour un unsigned char.

    
movsx eax, byte [rdi]Lit un octet et recopie le bit de signe : pour un char signé.

  • Deux opérandes mémoire. mov [rdi], [rsi] n'existe pas : il faut passer par un registre.
    •

    • 
    
  • Des tailles différentes : mov rax, ecx ne s'assemble pas. C'est le rôle de movzx et movsx.
    • 
    
  • Un immédiat en destination, évidemment.

Les combinaisons d'opérandes

Un immédiat fait 32 bits au plus

  
Sauf pour mov registre, immédiat, une constante est encodée sur 32 bits (ou 8), puis son signe est étendu à la taille de l'opération. Deux conséquences qui surprennent :

  
mov rax, 0x1122334455667788     ; ok : le seul cas d'immediat 64 bits
add rax, 0x7FFFFFFF             ; ok : tient sur 32 bits signes
and rax, 0xFFFFFFFF             ; piege : NASM avertit, la constante ne tient pas en 32 bits signes
mov eax, eax                    ; la bonne facon de garder les 32 bits bas
and rax, -16                    ; ok : -16 = 0xFFFFFFFFFFFFFFF0 apres extension

  
Pour utiliser une grande constante dans un calcul, la charger d'abord : mov rcx, 0x1122334455667788 puis add rax, rcx.

Additionner, soustraire, comparer

  
L'addition et la soustraction sont les mêmes instructions pour le signé et le non signé : grâce au complément à deux, les bits du résultat sont identiques. Seule la lecture des flags diffère, et c'est l'objet du chapitre suivant.

  
    
    
  • cmp a, b est un sub qui jette son résultat. test a, b est un and qui jette son résultat. Ils n'existent que pour les flags.
    • 
    
  • inc et dec valent add 1 et sub 1, sauf qu'ils laissent CF tranquille.
    • 
    
  • neg change le signe. not inverse les bits. La relation entre les deux : -x == ~x + 1.
    • 
    
  • lea additionne sans toucher aux flags et sans écraser ses opérandes : lea rax, [rdi + rsi + 1].
    • 
  


  
Multiplier

  
Deux générations d'instructions cohabitent. La forme ancienne, à un opérande, travaille sur rax et rdx sans le dire. La forme moderne, imul à deux ou trois opérandes, se comporte comme un add.

  

    
FormeCalculRegistres écrasés

    
imul rax, rsirax = rax * rsi, tronqué à 64 bitsrax seulement

    
imul rax, rsi, 10rax = rsi * 10rax seulement

    
mul rsi (64 bits)rdx:rax = rax * rsi, non signé, 128 bitsrax et rdx

    
mul esi (32 bits)edx:eax = eax * esirax et rdx

    
mul si (16 bits)dx:ax = ax * siax et dx

    
mul sil (8 bits)ax = al * silax

  

  
Utilise imul à deux opérandes par défaut, y compris pour du non signé : les 64 bits bas d'un produit sont les mêmes. Garde mul pour quand il te faut la moitié haute, par exemple pour détecter le débordement d'un calloc(n, size).


  
Diviser

  
div est l'instruction la plus piégeuse. Le dividende est implicite et fait le double de la taille du diviseur, réparti sur deux registres.

  

    
DiviseurDividendeQuotientRestePréparer avant

    
64 bits : div rcxrdx:raxraxrdxxor edx, edx · signé : cqo

    
32 bits : div ecxedx:eaxeaxedxxor edx, edx · signé : cdq

    
16 bits : div cxdx:axaxdxxor edx, edx · signé : cwd

    
8 bits : div claxalahmovzx eax, al · signé : cbw

  

  
    
    
  • Oublier de préparer rdx : le dividende contient des restes d'un calcul précédent, le quotient ne tient plus dans rax, et le processeur lève une exception. Le programme meurt avec SIGFPE, le même signal que pour une division par zéro.
    • 
    
  • Pas d'immédiat : div 10 n'existe pas. Il faut mov ecx, 10 puis div rcx.
    • 
    
  • rdx est écrasé, or c'est ton 3e argument : le mettre à l'abri d'abord.
    • 
    
  • Diviser par une puissance de deux : shr en non signé. En signé, sar seul arrondit vers moins l'infini, pas vers zéro comme le C : il faut la correction de div8 ci-dessous.
    • 
  

  
global divmod
global sdiv
global mulhi
global times10
global div8

section .text
; unsigned long divmod(unsigned long a, unsigned long b, unsigned long *rem)
divmod:
    mov rcx, rdx            ; rdx (3e argument) va etre ecrase par div
    mov rax, rdi            ; dividende, moitie basse
    xor edx, edx            ; dividende, moitie haute = 0
    div rsi                 ; rax = a / b, rdx = a % b
    mov [rcx], rdx          ; *rem = reste
    ret

; long sdiv(long a, long b)
sdiv:
    mov rax, rdi
    cqo                     ; rdx = 0 ou -1 selon le signe de rax
    idiv rsi
    ret

; unsigned long mulhi(unsigned long a, unsigned long b) : les 64 bits hauts du produit
mulhi:
    mov rax, rdi
    mul rsi                 ; rdx:rax = a * b sur 128 bits
    mov rax, rdx
    ret

; long times10(long x) : sans imul
times10:
    lea rax, [rdi + rdi*4]  ; x * 5
    add rax, rax            ; * 2
    ret

; long div8(long x) : x / 8 signe, arrondi vers zero comme en C
div8:
    lea rax, [rdi + 7]      ; pour les negatifs : on corrige avant de decaler
    test rdi, rdi
    cmovns rax, rdi         ; positif ou nul : pas de correction
    sar rax, 3
    ret

Instructions de chaînes

  
Cinq instructions sans opérande, qui utilisent toujours les mêmes registres. Combinées au préfixe rep, elles remplacent une boucle entière.

  

    
InstructionFaitLitÉcritAvec rep, c'est

    
movsb*rdi++ = *rsi++rsirdimemcpy

lodsbal = *rsi++rsialrarement utile

    
scasbcmp al, *rdi++al, rdiflagsmemchr, strlen (avec repne)

  • Le suffixe donne la taille de l'élément et le pas : b 1 octet, w 2, d 4, q 8.
    • 
    
  • rep répète rcx fois. repe s'arrête en plus dès que la comparaison diffère, repne dès qu'elle est égale.
    • 
    
  • Après un repne scasb ou un repe cmpsb, les pointeurs ont dépassé d'un cran l'octet qui a provoqué l'arrêt.
    • 
    
  • Si rcx vaut 0 au départ, rien n'est exécuté et les flags ne sont pas mis à jour.
    • 
    
  • Ces instructions écrasent rsi, rdi et rcx, qui sont aussi tes arguments 2, 1 et 4.
    • 
  

  
; void *ft_memset(void *dst, int c, size_t n)
global ft_memset
global ft_memcpy
global strlen_scas
global ft_memcmp

section .text
ft_memset:
    mov r8, rdi             ; dst pour le retour (r8 est libre : aucun call ici)
    mov eax, esi            ; al = l'octet a ecrire
    mov rcx, rdx            ; rcx = nombre de repetitions
    rep stosb               ; rcx fois : [rdi] = al, rdi++
    mov rax, r8
    ret

; void *ft_memcpy(void *dst, const void *src, size_t n)
ft_memcpy:
    mov rax, rdi            ; valeur de retour
    mov rcx, rdx
    rep movsb               ; rcx fois : [rdi] = [rsi], rdi++, rsi++
    ret

; size_t strlen_scas(const char *s)
strlen_scas:
    xor eax, eax            ; al = 0 : l'octet recherche
    mov rcx, -1             ; compteur au maximum : pas de limite
    repne scasb             ; avance tant que [rdi] != al ; s'arrete APRES le '\0'
    not rcx                 ; rcx = nombre d'octets parcourus, '\0' compris
    lea rax, [rcx - 1]      ; on retire le '\0'
    ret

; int ft_memcmp(const void *a, const void *b, size_t n)
ft_memcmp:
    xor eax, eax
    mov rcx, rdx
    test rcx, rcx           ; n == 0 : repe ne ferait aucun tour
    jz .done                ;   et laisserait des flags perimes
    repe cmpsb              ; avance tant que les octets sont egaux
    movzx eax, byte [rdi - 1]   ; les pointeurs ont depasse d'un cran
    movzx ecx, byte [rsi - 1]
    sub eax, ecx            ; 0 si tout etait egal
.done:
    ret


  
Sauts et appels

  
Le processeur exécute les instructions dans l'ordre de la mémoire, en avançant rip. Quatre instructions changent ce cours.

  

    
InstructionEffet sur ripEffet sur la pile

    
jmp ciblerip = cibleaucun

call ciblerip = cibleempile l'adresse de l'instruction qui suit le call

    
retrip = la valeur au sommet de la piledépile 8 octets

  

  
    
    
  • Une cible écrite comme un label est encodée en distance relative : le code fonctionne quelle que soit l'adresse où il est chargé.
    • 
    
  • Une cible écrite comme un registre ou de la mémoire (jmp rax, call [rdi + 8]) est une adresse absolue lue à l'exécution : pointeurs de fonction, tables de sauts.
    • 
    
  • call et ret ne savent rien des fonctions. Une « fonction » n'est qu'un label vers lequel on fait call, et qui finit par un ret avec la pile dans l'état où il l'a trouvée.
    •

Flags et conditions

  
Il n'y a pas de if en assembleur. Un calcul laisse une trace dans quelques bits du registre rflags, et un saut conditionnel lit ces bits. Tout test s'écrit donc en deux temps.

Les conditions

  
Un suffixe de condition est une formule sur les flags. Le même suffixe s'accroche à trois mnémoniques : jcc (sauter), setcc (écrire 0 ou 1 dans un octet), cmovcc (copier). Les noms se lisent après cmp a, b : jl saute si a < b.

  

  
Signé ou non signé
cmp est le même dans les deux cas. C'est le saut que tu choisis qui décide de l'interprétation. above / below (ja, jb) pour le non signé : tailles, adresses, unsigned char. greater / less (jg, jl) pour le signé : int, ssize_t. L'égalité est la même.


  
Pourquoi ces formules

  
cmp a, b calcule a - b. Chaque condition se déduit de ce qu'on sait d'une soustraction.

  
    
    
  • Égalité : a - b vaut zéro exactement quand a == b. D'où ZF.
    • 
    
  • Inférieur, non signé : si a < b, la soustraction doit emprunter. D'où jb = CF.
    • 
    
  • Inférieur, signé : si a < b, le résultat est négatif, donc SF = 1... sauf si la soustraction a débordé, auquel cas le signe obtenu est l'inverse du vrai signe. OF dit justement s'il y a eu débordement. Le vrai signe est donc « SF corrigé par OF » : a < b quand SF != OF. D'où jl.
    • 
    
  • Les autres s'obtiennent en combinant avec ZF : jle = jl ou égal, jg = ni jl ni égal, jbe = jb ou égal, ja = ni jb ni égal.
    • 
  

  
Après test a, a, les flags décrivent a lui-même : jz si nul, js si négatif, jle si négatif ou nul, jg si strictement positif.

Tester un intervalle en une comparaison

  
Pour lo <= c && c <= hi, on soustrait lo puis on compare en non signé à hi - lo. Si c était sous lo, la soustraction a « fait le tour » et donne un nombre énorme, donc le test échoue aussi.

  
; int ft_isdigit(int c) : '0' <= c && c <= '9' en une seule comparaison
ft_isdigit:
    lea eax, [rdi - '0']    ; eax = c - '0'
    cmp eax, 9              ; non signe : si c < '0', eax est devenu enorme
    setbe al
    movzx eax, al           ; etend le booleen sur 32 bits
    ret

    mov eax, edi

    sub eax, 32             ; 'a' - 'A'
.done:
    ret

Pour des cas numérotés de 0 à N, pas besoin d'une cascade de cmp : on range les adresses des blocs dans un tableau, et la valeur sert d'index. Un seul saut, quel que soit le nombre de cas.

  
; int calc(unsigned op, int a, int b)
;   switch (op) { case 0: a + b; case 1: a - b; case 2: a * b; default: 0; }
default rel
global calc

section .text
calc:
    cmp edi, 2
    ja .default             ; hors de la table (non signe)
    mov edi, edi            ; efface les 32 bits hauts de rdi
    lea rax, [rel table]
    jmp [rax + rdi*8]       ; saute a l'adresse rangee dans table[op]
.add:
    lea eax, [rsi + rdx]
    ret
.sub:
    mov eax, esi
    sub eax, edx
    ret
.mul:
    mov eax, esi
    imul eax, edx
    ret
.default:
    xor eax, eax
    ret

section .data
table:  dq calc.add, calc.sub, calc.mul     ; trois adresses de code

Écrire un wrapper comme la libc

  
ft_write reçoit ses arguments dans rdi, rsi, rdx, exactement là où le syscall les attend : il n'y a qu'à poser le numéro. Le seul travail est la gestion d'erreur. errno étant propre à chaque thread, on ne peut pas y accéder par un simple label : la libc fournit __errno_location() qui renvoie son adresse.

  
; ssize_t ft_write(int fd, const void *buf, size_t count)
;   les arguments sont deja dans rdi, rsi, rdx : rien a deplacer
global ft_write
extern __errno_location

section .text
ft_write:
    mov eax, 1                  ; syscall write
    syscall
    test rax, rax
    js .error                   ; retour negatif = -errno
    ret
.error:
    neg rax                     ; rax = errno (positif)
    push rax                    ; sauvegarde + realigne la pile sur 16
    call __errno_location wrt ..plt   ; rax = &errno
    pop rdx
    mov [rax], edx              ; errno est un int : 32 bits
    mov rax, -1
    ret

  
Le push rax fait deux choses à la fois : il met le code d'erreur à l'abri du call, et il réaligne la pile sur 16. Le détail ligne par ligne est au chapitre 13.

errno

  
errno est une invention de la libc, pas du kernel. Comprendre qui fait quoi suffit à écrire ft_read et ft_write correctement.

  

    
QuiCe qu'il fait en cas d'erreur

    
Le kernelRenvoie dans rax le code d'erreur négatif : -9 pour EBADF. Il ne connaît pas errno.

    
Le wrapper de la libcDétecte ce retour négatif, range le code positif dans errno, et renvoie -1.

    
Le programme CVoit -1, consulte errno, appelle perror ou strerror.

  

  
Écrire ft_write, c'est donc écrire la ligne du milieu.


  
Où est errno

  
errno n'est pas une variable globale ordinaire : chaque thread a la sienne. On ne peut donc pas écrire mov [errno], eax. La libc fournit une fonction qui renvoie l'adresse de la bonne case :

  
; en C, errno est une macro :   #define errno (*__errno_location())
extern __errno_location         ; int *__errno_location(void);

  
Écrire dans errno se fait donc en deux temps : appeler __errno_location, puis écrire un int à l'adresse reçue dans rax.


  

    
Du retour du kernel au retour de ta fonction

    

    

  


  
Le wrapper complet

  
; ssize_t ft_read(int fd, void *buf, size_t count)
default rel
global ft_read
extern __errno_location

section .text
ft_read:
    xor eax, eax                ; syscall read = 0
    syscall                     ; rax = octets lus, ou -errno
    cmp rax, -4095              ; comparaison non signee :
    jae .error                  ;   [-4095, -1] = les plus grandes valeurs
    ret                         ; succes : on ne touche pas a errno

.error:
    neg rax                     ; -9 devient 9 (EBADF)
    push rax                    ; a l'abri du call, et pile realignee
    call __errno_location wrt ..plt   ; rax = &errno
    pop rcx                     ; rcx = le code d'erreur
    mov [rax], ecx              ; *(&errno) = code, sur 32 bits
    mov rax, -1                 ; valeur de retour d'erreur
    ret

  
Chaque ligne du bloc .error évite un piège précis :

  
    
    
  • neg rax : le kernel a renvoyé -9, errno doit valoir 9.
    • 
    
  • push rax : __errno_location est une fonction C, elle écrase rax avec sa valeur de retour et peut détruire tous les caller-saved. Le code d'erreur doit être mis à l'abri avant. Ce push unique réaligne aussi la pile sur 16.
    • 
    
  • wrt ..plt : la fonction vit dans la libc partagée.
    • 
    
  • pop rcx et pas pop rax : rax contient maintenant l'adresse d'errno, il ne faut pas l'écraser.
    • 
    
  • mov [rax], ecx : errno est un int, donc 4 octets. Écrire rcx déborderait de 4 octets sur ce qui suit.
    • 
    
  • mov rax, -1 : en 64 bits, parce que le type de retour est ssize_t.
    • 
  

  
En cas de succès
On ne touche pas à errno. La norme dit qu'une fonction qui réussit ne le remet pas à zéro : c'est à l'appelant de faire errno = 0 avant s'il veut tester après.


  
Détecter l'erreur : js ou la plage -4095

test rax, rax / js .error« le retour est négatif »read, write, open, close : leur retour valide n'est jamais négatif.

Lire errno, ou le poser soi-même

  
Même mécanisme dans l'autre sens. Une fonction à toi qui échoue pour une raison qui lui est propre peut choisir son code : ENOMEM, EINVAL...

  
; int get_errno(void) : lire errno
default rel
global get_errno
global fail_nomem
extern __errno_location

section .text
get_errno:
    sub rsp, 8                  ; aligne la pile pour le call
    call __errno_location wrt ..plt
    mov eax, [rax]              ; eax = errno
    add rsp, 8
    ret

; void *fail_nomem(void) : poser errno soi-meme et renvoyer NULL
fail_nomem:
    sub rsp, 8
    call __errno_location wrt ..plt
    mov dword [rax], 12         ; errno = ENOMEM
    xor eax, eax                ; return NULL
    add rsp, 8
    ret

  
Quand tu appelles malloc et qu'il renvoie NULL, il a déjà posé errno = ENOMEM : tu n'as qu'à propager le NULL, comme le fait ft_strdup.

Structs

  
Une struct n'existe pas pour le processeur. C'est un bloc d'octets, et chaque champ est un décalage par rapport au début.

  
node->next en C devient [rdi + 8] en assembleur. NASM propose struc pour donner des noms à ces décalages plutôt que d'écrire des nombres magiques :

  
struc t_list
    .data:  resq 1      ; t_list.data = 0
    .next:  resq 1      ; t_list.next = 8
endstruc                ; t_list_size = 16, defini automatiquement

    mov rax, [rdi + t_list.next]    ; rax = node->next
    mov edi, t_list_size            ; sizeof(t_list)

  
struc ne réserve aucune mémoire : il définit seulement des constantes. Pour créer une instance initialisée dans .data, il y a istruc :

  
section .data
premier:
    istruc t_list
        at t_list.data, dq 0
        at t_list.next, dq 0
    iend


  
Alignement et padding

  
Le compilateur C place chaque champ à une adresse multiple de sa taille, et insère des octets de remplissage pour y arriver. La taille totale est arrondie au plus grand alignement. Allocations

  
Trois endroits où ranger des données, avec trois durées de vie.

  

    
OùCommentDurée de viePour quoi

    
Statique.data, .rodata, .bssTout le programmeConstantes, chaînes, globales, gros buffers fixes.

Sur la pile

  
    push rbp
    mov rbp, rsp
    sub rsp, 64             ; char buf[64], et la pile reste alignee
    lea rdi, [rbp - 64]     ; rdi = buf
    ; ... utiliser buf ...
    leave                   ; libere tout d'un coup
    ret

  
Ne renvoie jamais l'adresse d'un buffer de pile : il cesse d'exister au ret, comme une variable locale en C.


  
Sur le tas, avec malloc

  
malloc est une fonction C comme une autre : taille dans rdi, pointeur dans rax, NULL en cas d'échec. Elle détruit tous les registres caller-saved, donc tout ce dont tu as encore besoin après doit être dans rbx ou r12-r15.

  
; char *ft_strdup(const char *s)
global ft_strdup
extern malloc
extern ft_strlen
extern ft_strcpy

section .text
ft_strdup:
    push rbx                    ; callee-saved, et realigne la pile
    mov rbx, rdi                ; s survit aux call dans rbx
    call ft_strlen              ; rax = strlen(s)
    lea rdi, [rax + 1]          ; +1 pour le '\0'
    call malloc wrt ..plt       ; rax = nouveau buffer
    test rax, rax
    jz .done                    ; malloc a echoue : on renvoie NULL
    mov rdi, rax                ; dst
    mov rsi, rbx                ; src
    call ft_strcpy              ; renvoie dst dans rax
.done:
    pop rbx
    ret


  
Sans libc : mmap

  
malloc lui-même obtient sa mémoire du kernel avec mmap (ou brk). Tu peux l'appeler directement : le kernel te donne des pages entières de 4096 octets, déjà à zéro.

  
; void *page_alloc(size_t size) : memoire anonyme via mmap, sans libc
global page_alloc

section .text
page_alloc:
    mov rsi, rdi        ; length
    xor edi, edi        ; addr = NULL : le kernel choisit
    mov edx, 3          ; PROT_READ | PROT_WRITE
    mov r10d, 0x22      ; MAP_PRIVATE | MAP_ANONYMOUS  (r10, pas rcx !)
    mov r8, -1          ; fd = -1
    xor r9d, r9d        ; offset = 0
    mov eax, 9          ; syscall mmap
    syscall
    cmp rax, -4095      ; entre -4095 et -1 : c'est une erreur
    jae .fail
    ret
.fail:
    xor eax, eax        ; on renvoie NULL
    ret

  
Pour rendre la mémoire : syscall 11, munmap(addr, length).

strlen : une boucle, zéro sauvegarde

  
Fonction feuille. rax sert à la fois d'index et de valeur de retour.

  
; size_t ft_strlen(const char *s)
;   rdi = s          retour : rax
global ft_strlen

section .text
ft_strlen:
    xor eax, eax                ; len = 0
.loop:
    cmp byte [rdi + rax], 0     ; s[len] == '\0' ?
    je .done
    inc rax
    jmp .loop
.done:
    ret


  
strcpy : charger un octet proprement

  
On teste le caractère après l'avoir copié, ce qui copie le \0 final sans cas particulier.

  
; char *ft_strcpy(char *dst, const char *src)
;   rdi = dst, rsi = src     retour : rax = dst
global ft_strcpy

section .text
ft_strcpy:
    mov rax, rdi                ; la valeur de retour, on n'y touche plus
    xor ecx, ecx                ; i = 0
.loop:
    movzx edx, byte [rsi + rcx] ; c = src[i]
    mov [rdi + rcx], dl         ; dst[i] = c
    inc rcx
    test dl, dl                 ; c == 0 ? (on a deja copie le '\0')
    jnz .loop
    ret


  
strcmp : la comparaison en unsigned char

  
La norme C dit que strcmp compare les caractères comme des unsigned char. D'où movzx et non movsx : avec une extension signée, "\xff" serait plus petit que "a" et tes tests contre le vrai strcmp échoueraient.

  
; int ft_strcmp(const char *s1, const char *s2)
;   rdi = s1, rsi = s2       retour : eax (<0, 0, >0)
global ft_strcmp

section .text
ft_strcmp:
.loop:
    movzx eax, byte [rdi]       ; a = (unsigned char)*s1
    movzx ecx, byte [rsi]       ; b = (unsigned char)*s2
    cmp eax, ecx
    jne .diff                   ; differents : on s'arrete
    test eax, eax
    jz .diff                    ; egaux et nuls : fin des deux chaines
    inc rdi
    inc rsi
    jmp .loop
.diff:
    sub eax, ecx                ; a - b, deja etendus sur 32 bits
    ret


  
split : tout à la fois

  
Avant d'écrire une fonction de cette taille, décide sur papier quel registre contient quoi. Ici il y a cinq valeurs qui doivent survivre à des malloc : il faut donc cinq registres callee-saved, et cinq push, ce qui tombe bien pour l'alignement.

  

    
RegistreContenuÉquivalent C

    
rbxposition courante dans la chaîneconst char *s

    
r12ble séparateurchar c

    
r13le tableau de résultatschar **tab

    
r14nombre de mots déjà rangéssize_t i

    
r15longueur du mot en courssize_t len

  

  
L'algorithme : compter les mots, allouer (n + 1) pointeurs, puis répéter « sauter les séparateurs, mesurer le mot, l'allouer, le copier ». Si un malloc échoue en route, on libère tout ce qui a déjà été alloué.

  
; char **ft_split(const char *s, char c)
;   rdi = s, sil = c       retour : tableau termine par NULL
global ft_split
extern malloc
extern free

section .text

; --- size_t count_words(const char *s, char c) ---------------------
; fonction feuille : n'appelle personne, n'utilise que des scratch
count_words:
    xor eax, eax                ; nb = 0
    xor ecx, ecx                ; dans_un_mot = 0
.loop:
    movzx edx, byte [rdi]
    test dl, dl
    jz .done
    cmp dl, sil
    je .sep
    test ecx, ecx
    jnz .next                   ; deja dans un mot
    inc rax                     ; debut d'un nouveau mot
    mov ecx, 1
    jmp .next
.sep:
    xor ecx, ecx
.next:
    inc rdi
    jmp .loop
.done:
    ret

; --- ft_split ------------------------------------------------------
; rbx = curseur dans s     r12b = separateur    r13 = tableau
; r14 = index du mot       r15  = longueur du mot courant
ft_split:
    push rbx
    push r12
    push r13
    push r14
    push r15                    ; 5 push + adresse de retour = 48 : aligne
    xor eax, eax
    test rdi, rdi
    jz .ret                     ; s == NULL -> NULL
    mov rbx, rdi
    movzx r12d, sil

    call count_words            ; rdi et sil sont encore en place
    lea rdi, [rax*8 + 8]        ; (nb + 1) * sizeof(char *)
    call malloc wrt ..plt
    test rax, rax
    jz .ret
    mov r13, rax
    xor r14d, r14d              ; i = 0

.skip:                          ; saute les separateurs
    movzx eax, byte [rbx]
    test al, al
    jz .finish
    cmp al, r12b
    jne .measure_init
    inc rbx
    jmp .skip

.measure_init:
    xor r15d, r15d              ; len = 0
.measure:                       ; avance jusqu'au separateur ou '\0'
    movzx eax, byte [rbx + r15]
    test al, al
    jz .copy
    cmp al, r12b
    je .copy
    inc r15
    jmp .measure

.copy:
    lea rdi, [r15 + 1]
    call malloc wrt ..plt
    test rax, rax
    jz .cleanup
    mov [r13 + r14*8], rax      ; tab[i] = mot
    mov rdi, rax                ; destination
    mov rsi, rbx                ; source
    mov rcx, r15                ; compteur
    rep movsb                   ; copie rcx octets, rdi/rsi avancent
    mov byte [rdi], 0           ; rdi pointe juste apres le mot
    add rbx, r15
    inc r14
    jmp .skip

.finish:
    mov qword [r13 + r14*8], 0  ; tab[i] = NULL
    mov rax, r13
.ret:
    pop r15
    pop r14
    pop r13
    pop r12
    pop rbx
    ret

.cleanup:                       ; un malloc a rate : on libere tout
    test r14, r14
    jz .free_tab
    dec r14
    mov rdi, [r13 + r14*8]
    call free wrt ..plt
    jmp .cleanup
.free_tab:
    mov rdi, r13
    call free wrt ..plt
    xor eax, eax
    jmp .ret

  
    
    
  • lea rdi, [rax*8 + 8] calcule (n + 1) * 8 en une instruction, sans imul.
    • 
    
  • rep movsb remplace une boucle de copie : il copie rcx octets de [rsi] vers [rdi] et laisse rdi juste après le dernier octet écrit, pile là où poser le \0.
    • 
    
  • count_words n'est pas global : c'est l'équivalent d'une fonction static.
    • 
    
  • Testé avec "  hello  world foo ", la chaîne vide, une chaîne de séparateurs seuls, et sous AddressSanitizer.

Curiosités

  

    
Little-endian
L'entier 0x11223344 est stocké en mémoire dans l'ordre 44 33 22 11 : l'octet de poids faible à l'adresse la plus basse.

    
Longueur variable
Une instruction x86-64 fait entre 1 et 15 octets. ret en fait un seul (C3), mov rax, imm64 en fait dix.

    
nop est un échange
L'opcode 90 de nop est historiquement celui de xchg eax, eax.

    
Les noms ont une histoire
Accumulator, Base, Counter, Data, Source Index, Destination Index : les rôles du 8086 de 1978, que rep movsb utilise encore.

    
strlen en trois instructions
xor eax, eax, mov rcx, -1, repne scasb cherche le zéro tout seul. La longueur se déduit ensuite de rcx avec not rcx / dec rcx.

    
ah ne va pas partout
ah, bh, ch, dh ne peuvent pas apparaître dans la même instruction que sil, dil ou r8-r15. Une contrainte d'encodage héritée du 32 bits.

    
inc garde la retenue
inc et dec ne modifient pas CF, contrairement à add reg, 1. Utile dans une boucle qui additionne de grands nombres.

    
int 0x80
C'est l'ancienne porte d'entrée 32 bits vers le kernel, avec d'autres numéros (write = 4). En 64 bits elle tronque les pointeurs : toujours syscall.
